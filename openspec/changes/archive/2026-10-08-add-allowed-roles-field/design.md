# Design

## Context

All responses flow through `ApiResponse::Set()` (`app/core/helpers/api_response.php`), which merges module-supplied `$data` into a catalog envelope and reserves the keys `code`, `http_code`, `message`, `meta`. Authentication and per-method role lists live in `ModuleHandler::Validate()` (`app/core/auth/module.access.controller.php`), which reads each module's `$accepted_methods` — the only place where the create/edit/delete role declarations for a module are visible — and defines `AUTHENTICATED` only once a request is established as authenticated. The OpenAPI contract is generated by `tools/generate-openapi.php` into `api/docs/openapi.json` (mirrored under `httpdocs/api/docs/`), with `tests/OpenApiSyncTest.php` failing when the published file drifts from the generator. See proposal.md for motivation and `specs/allowed-roles-disclosure/spec.md` for the behavior contract.

## Goals / Non-Goals

**Goals:**

- One injection point so every post-validation response carries the field consistently (successes and in-method errors alike).
- Anonymous responses, including rejected authentications and pre-validation responses, never leak role lists.
- Contract and runtime stay in lockstep via the existing sync check.

**Non-Goals:**

- No changes to authorization decisions themselves (`ModuleHandler::Authenticate()` behavior is untouched).
- No role-name resolution, database changes, or new endpoints.
- No disclosure of per-field role restrictions (`$moduleFields['roles']`) or row-level `edit_roles` — only module-level method role lists.

## Decisions

1. **Derive in `ModuleHandler::Validate()`, inject in `ApiResponse::Set()`.**
   `Validate()` is the only code that sees the module's full `$accepted_methods`; it aggregates the `store`/`update`/`destroy` role lists into `{create, edit, delete}` and hands them to the response path (static setter on `ApiResponse`, e.g. `SetAllowedRoles()`).
   *Alternatives:* re-reading module `index.php` from `ApiResponse` (impossible — `$accepted_methods` is local to the module) or computing in `midelware.php` (would duplicate `$accepted_methods` parsing per module).

2. **Presence rule: inject iff `AUTHENTICATED` is defined and true at response time.**
   `ApiResponse::Set()` checks the constant, so responses from authenticated methods (including validation/business errors) include the field, while 401/403 rejections (constant never defined), anonymous calls, and pre-validation responses (e.g. rate limiter) omit it. This matches the user's chosen rule: presence follows the session state, not the method's declared auth flag.
   *Alternative:* gating on the method's declared `[auth, roles]` slot — rejected because it would omit the field on public methods called with a valid token and include it on rejected requests.

3. **Reserved key.** `allowed_roles` joins the reserved list in the extra-data merge loop, so module data can never spoof or replace it (see `specs/api-response-envelope/spec.md`).

4. **Shape decisions.** Roles stay integer IDs (the system's canonical role representation per authentication-and-authorization); action keys are omitted when the module does not declare them; an empty array means "any authenticated role"; an authenticated response from a module with no standard CRUD actions yields `{}`. The value reflects the module's declarations for the current request, regardless of `REQUEST_TYPE`.

5. **OpenAPI: conditional property keyed off security.** The generator adds an optional `allowed_roles` object property (with `create`/`edit`/`delete` arrays of integers) to the shared `ResponseEnvelope` schema for operations that declare the bearer security scheme, and omits it otherwise. Regenerate both published copies and keep `OpenApiSyncTest` green.
   *Alternative:* a separate `AuthenticatedResponseEnvelope` schema referenced only by secured operations — cleaner isolation, but touches every operation's `$ref` for the same observable result.

## Risks / Trade-offs

- [Existing tests assert exact envelope contents] → `tests/ApiResponseTest.php` (and any contract fixtures) must be updated alongside the injection; run the full PHPUnit suite.
- [Disclosing role IDs to any authenticated caller] → accepted: role IDs are already visible to clients via the `roles` module for permitted callers; only IDs (not names) are disclosed, and anonymous callers see nothing.
- [Modules that respond before `Validate()` runs] → they omit the field by construction (no established session yet), which the spec allows; flagged in tasks so reviewers verify no in-scope endpoint regresses.
- [Generator and hand-edited contract drift] → mitigated by regenerating via `tools/generate-openapi.php` only and relying on `OpenApiSyncTest`.

## Migration Plan

Additive, backward-compatible change with no schema or configuration migration: deploy code, regenerate and publish the OpenAPI document, run the test suite. Rollback = revert the code change and regenerate the contract; clients ignore unknown fields, so no coordinated release is needed.

## Open Questions

None — field shape (`allowed_roles` nested by action) and presence rule (`AUTHENTICATED === true`) were confirmed with the requester.
